## Dispositions and corrections

| Alert | Evidence and disposition | Correction and regression coverage |
| --- | --- | --- |
| [#37: polynomial regex](https://github.com/Kriordan/personal_portfolio/security/code-scanning/37) | **Already bounded / partially mitigated; no reachable ReDoS demonstrated.** Authenticated Jobwizard extraction input reaches `target_profile`, also used by capture and saved-job support checks. Every call first passes `safe_listing_url`: at most 2,048 URL characters and IDNA-validated DNS labels of at most 63 bytes. Oversized repeated-hyphen inputs already fail before the flagged Workday regex. | Replace the whole-host backtracking regex with separate hostname-label comparisons. Preserve exact Workday suffix, ASCII tenant/shard syntax, `/job/`, HTTPS/port/query restrictions and the existing other platforms. Tests cover 63-character label boundaries, 100,000 hyphens, Unicode/shard/suffix impostors, supported routes, and rejection before DNS/provider calls. These guard tests also pass on baseline; they are evidence of existing mitigation, not a reproduced DoS. |
| [#34: exception details](https://github.com/Kriordan/personal_portfolio/security/code-scanning/34) | **Partially mitigated by current producers.** Authenticated sync catches `SyncError` and serializes `str(error)`. Current construction sites substitute fixed messages for provider errors, but arbitrary exception text is permitted by the type and also reaches web flash messages and stored receipts. Injecting a synthetic secret-bearing `SyncError` through the importer on baseline exposes the detail in JSON. This is a boundary regression demonstration, not proof that current providers can construct that exception. | Give `SyncError` stable codes selecting fixed public messages/statuses. API, website and durable receipts use those mapped messages, independent of exception arguments. Unknown codes become the existing generic 500. Tests poison exception arguments for every known code and an unknown code, inspect JSON/flash/receipt text, and retain provider 401/configuration → 503, provider/network → 502, unexpected → 500, and busy/interrupted → 409 behavior. Existing rollback and receipt replay tests remain. |
| [#9: DOM text as HTML](https://github.com/Kriordan/personal_portfolio/security/code-scanning/9) | **False positive for attacker reachability in the current configuration.** SARIF points to `JSON.parse(script.textContent)` → `config.doneUrl` → `window.location.href`, not Markdown rendering. The only production producer is Jinja `url_for('learning.index')` inside `tojson`; card text does not supply this URL. An injected fixture `javascript:` destination does demonstrate why that generic sink is risky if its producer changes. | Replace the button/JavaScript navigation with a normal anchor whose destination is generated by Jinja; remove `doneUrl` from JSON. Render the real template with adversarial card text and verify escaping and the local anchor. The browser harness proves malicious legacy configuration cannot execute on Done, and still tests Markdown sanitization/fallback, review completion and summary. No dismissal requested because the unnecessary sink is removed. |
| [#8: randomness](https://github.com/Kriordan/personal_portfolio/security/code-scanning/8) | **False positive for a security-sensitive value today.** The timestamp/`Math.random()` value is a review metrics `session_id`, not a login credential, authorization token or idempotency key. Reviews are scoped to the authenticated user; durable receipts use a separate cryptographic request UUID and user ID. | Use `crypto.randomUUID()` for the session too. This API is already required by the same browser review flow. Browser tests verify the value comes from Web Crypto, remains stable across cards and retries, differs on a fresh session, and stays distinct from per-attempt request IDs. There is no insecure fallback. |
| [#3: redirect](https://github.com/Kriordan/personal_portfolio/security/code-scanning/3) | **Reachable redirect defect with partial protection.** Successful website login reads `next`; the old `urlsplit(...).netloc` check rejects ordinary external URLs but allows a scheme with empty netloc. Baseline returns `Location: https:///evil.test`, which the browser URL parser resolves to `https://evil.test/`. Malformed IPv6 authorities also raise rather than falling back. Werkzeug percent-encodes backslashes, so those cases alone are not claimed as demonstrated external redirects. | Accept only targets without schemes/authorities, backslashes, control characters, surrounding whitespace or a `//` prefix, catching parser errors. Tests exercise actual login POSTs, reject adversarial forms, preserve local relative/absolute paths, query strings and fragments, and preserve pending invitation priority. Existing authenticated/unverified login behavior is unchanged. |
