# Expo Wishlist CRUD with Image Upload (`implement-expo-wishlist`)

Date: 2026-07-07
Todo ID: `implement-expo-wishlist`

## Objective

Add wishlist gift browsing, creation, editing, and deletion to the Expo mobile app against the existing `/api/v1/wishlist` endpoints, including optional gift image attachment via the device photo library.

## Scope Delivered

- Typed wishlist API client (`mobile/src/lib/wishlist-api.ts`) covering all five gift endpoints plus TanStack Query key factory.
- Multipart `FormData` support in the shared API client (`mobile/src/lib/api-client.ts`) so image uploads reuse the existing JWT attach/refresh/retry pipeline.
- Reusable gift form component with image picking (`mobile/src/components/gift-form.tsx`).
- Three new screens: wishlist overview (`mobile/src/app/wishlist/index.tsx`), gift creation (`mobile/src/app/wishlist/new.tsx`), and gift detail with inline edit and delete (`mobile/src/app/wishlist/[id].tsx`).
- Navigation registration in the root stack and a Wishlist button on the home screen.
- `expo-image-picker` dependency (SDK 57 compatible) with its config plugin and iOS photo permission message in `mobile/app.json`.

## Prior Art / Context

- Screen structure, query/mutation patterns, redirect-on-unauthenticated behavior, and styling all mirror the existing learning screens (`mobile/src/app/learning/`) and list detail screen (`mobile/src/app/lists/[id].tsx`).
- Payload shapes mirror `project/api/wishlist.py` and `wishlist_service.serialize_gift()`: gifts are `{ id, title, body, image_url, timestamp, user_id }`.
- The Flask API reads images from `request.files["image"]` and accepts JSON or form fields for `title`/`body`, which dictated the multipart approach.

## Architecture and Design Choices

### 1) FormData support in the shared API client

- `rawRequest` now detects `FormData` bodies: it skips the `Content-Type: application/json` header (fetch sets `multipart/form-data` with the boundary itself) and passes the body through unserialized.
- Chosen over a separate upload helper so multipart requests get the same 401-refresh-retry and unauthorized-listener behavior for free.
- JSON remains the default; only wishlist create/update with an attached image uses FormData.

### 2) Conditional multipart vs JSON request body

- `giftRequestBody()` in `wishlist-api.ts` returns plain JSON when no image is attached and FormData (with `title`, `body`, and `image` parts) when one is.
- React Native FormData accepts `{ uri, name, type }` file descriptors; the `GiftImageInput` type models this and is cast at the single `form.append` call site.
- The backend replaces the image only when a file is present, so text-only updates never touch S3.

### 3) Shared `GiftForm` component

- One component (`mobile/src/components/gift-form.tsx`) backs both the create and edit screens: title/body inputs, image preview, pick/remove image buttons, submit button, and error display.
- Edit mode shows the existing remote `image_url` until a new local image is picked; the API has no image-removal semantics, so "Remove" only clears a newly picked local image.
- Image picking uses `ImagePicker.requestMediaLibraryPermissionsAsync()` then `launchImageLibraryAsync({ mediaTypes: ['images'], allowsEditing: true, quality: 0.8 })` per the Expo SDK 57 docs.

### 4) Detail screen with inline edit and confirmed delete

- `wishlist/[id].tsx` toggles between a read view and the `GiftForm` via local `isEditing` state rather than a separate edit route, keeping the route table small.
- Delete requires confirmation: native `Alert.alert` with a destructive action, falling back to `window.confirm` on web where `Alert.alert` is a no-op.
- Mutations update the query cache directly for the edited gift and invalidate the overview list; delete removes the detail query and navigates back.

### 5) Typed routes regeneration

- The repo has `experiments.typedRoutes` enabled, so `router.push('/wishlist')` initially failed `tsc` until `.expo/types/router.d.ts` was regenerated by briefly running `expo start`.

## API Contract

Consumes the existing `/api/v1/wishlist` endpoints (all JWT-protected):

- `GET /wishlist/gifts` → `{ gifts: Gift[] }`
- `POST /wishlist/gifts` (JSON or multipart with `image`) → `{ gift }` (201)
- `GET /wishlist/gifts/:id` → `{ gift }`
- `PUT /wishlist/gifts/:id` (JSON or multipart with `image`) → `{ gift }`
- `DELETE /wishlist/gifts/:id` → `{ message }`

`Gift` shape: `{ id: number, title: string, body: string, image_url: string | null, timestamp: string | null, user_id: number }`.

## Known Gaps / Follow-ups

- No end-to-end manual test of image upload; S3 upload also silently no-ops server-side when `WISHLIST_S3_BUCKET` or AWS credentials are absent, so a gift can save without its image.
- No way to remove an existing remote image (backend has no such operation).
- Image quality is fixed at 0.8 with no client-side size cap; very large originals still upload after editing.

## How to Run (Current)

1. Start the Flask API locally (see the backend runbook) with `WISHLIST_S3_BUCKET` and AWS credentials set if you want real image uploads.
2. In `mobile/`, run `npx expo start` and open the app in a simulator or Expo Go.
3. Sign in, tap **Wishlist** on the home screen.
4. Tap **Add Gift**, fill in title/description, optionally attach a photo, and submit.
5. Tap a gift row to view it; use **Edit** to change fields or replace the image, or **Delete** (with confirmation) to remove it.
