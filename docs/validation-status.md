## Recovery fixes and local validation

Four defects were reproduced and fixed in the mobile extraction session:

1. Definitively rejected reads (including rate limits, conflicts and explicitly disabled extraction) retained their recovery request and could reopen as unknown work. Clear that request after a definitive rejection, retaining it if durable cleanup fails.
2. An unclassified HTTP 503 was treated as definitive even if work had committed. Keep the same UUID and recover by reading its receipt; only the coded `unavailable` response is a definitive 503 rejection.
3. A late rejection from a disposed account could clear another account's pending request. Ignore responses after disposal before touching recovery storage.
4. Expired receipts left stale review/continuation/retry actions. Clear the expired result/request so deliberate fresh extraction is available.

Regression tests cover these transitions, account isolation and retention of a ready source when summarization is rate-limited. The initial three regression cases failed before the fix. ## Protected links and account sessions — October 27

PR #132 was squash-merged as `d7114bc67d9c6bd1e765497e4597fabf46e3d2e2` at 17:41 UTC after all seven checks passed. This follow-up uses that baseline and the same disposable local hosts described above. **Zero cloud builds**, no deployment, no real provider requests, no production data changes, and no credential changes. **Account-session defect reproduced and fixed in [PR #133](https://github.com/Kriordan/personal_portfolio/pull/133), with physical preview acceptance and merge authorized October 27:** the API client's global refresh could use the next account's refresh token to retry an old write, or let an old refresh overwrite the new account's token. The original code failed both focused reproductions. Requests now retain their session version through token reads, network responses, response parsing, refresh and retry. Refresh deduplication is per session; an old completion cannot clear the new refresh. Token reads/writes/deletes are serialized and account changes invalidate pending requests immediately. Explicit sign-out no longer waits on the stateless Flask logout route. Missing-account cleanup likewise invalidates tokens before awaiting other cleanup and cannot clear a later login.
